Rules used by the sandbox

    Data Ingest: wearable CSV validation

    Upload a CSV with a timestamp column and a CGM glucose column (mg/dL); heart_rate, hrv, steps_15m, sleep_stage, meal_carbs_g and insulin_units are optional. The file is read in your browser and never leaves it. Five checks run on the parsed rows. This page validates only: scoring new data needs the Python pipeline (models/train_fusion_model.py).

    No file to hand?

    The sample is the selected patient's first 12 h of synthetic wearable data in the GlycoTwin schema, without labels or model outputs. Edit it and upload it to see the checks react.

    Data
    • 200 synthetic patients × 664 labelled windows = 132,800 windows. Each patient has 7 days of 15-min data (672 readings); the final 2 h (8 readings) has no 2-h label.
    • Labels: 128,086 no event · 1,012 hypo <70 · 3,702 hyper >250 (next 2 h).
    • CGM readings <70 mg/dL: 409 (of which 35 <54, ADA Level 2), in 37 of 200 patients.
    • Insulin-treated personas: 3 of 200; 0 of them in the held-out split.
    • 34 model inputs = 18 wearable + 16 EHR.
    Model
    • scikit-learn HistGradientBoostingClassifier (3 classes: none / hypo / hyper in next 2 h) and HistGradientBoostingRegressor (glucose exactly 2 h ahead); max_iter=150, learning_rate=0.08, max_depth=6, random_state=42; classifier uses class_weight="balanced".
    • Alert rule: hypo if hypo score ≥ 0.51, else hyper if hyper score ≥ 0.52. Thresholds chosen by F2 score on out-of-fold predictions of the training patients only.
    • Latency: 14.6 ms median per single window (p95 21.7 ms), 8.4 µs per window batched; CPU only, measured by models/evaluate.py on one machine (the figures vary slightly from run to run). This page does not run the model: it replays outputs computed when the page was built.
    Model inputs

    Wearable (18): glucose_cgm, glucose_velocity_15m, glucose_velocity_30m, glucose_mean_1h, glucose_std_1h, heart_rate, hr_mean_1h, hrv, hrv_mean_1h, steps_15m, steps_sum_1h, steps_sum_2h, meal_carbs_g, carbs_sum_2h, insulin_units, insulin_sum_2h, hour_of_day, sleep_stage

    EHR (16): age, gender, bmi, diabetes_duration_years, baseline_hba1c, fasting_glucose_mg_dl, systolic_bp, diastolic_bp, egfr, diet_profile, primary_medication, insulin_regimen, clinical_risk_tier, prior_hypo_episodes_12m, family_history_t2d, tcf7l2_rs7903146_risk_alleles

    Limitations
    • Synthetic data only (data/generate_datasets.py). Simulator parameters are illustrative; population ranges are loosely informed by published Indian literature and are not calibrated to any dataset. Results do not transfer to real patients.
    • Risk scores are uncalibrated model outputs, not the probability of an event.
    • Precision is modest: 52.3% for hypo and 36.4% for hyper alerts on held-out windows; most alarms are not followed by an event.
    • No insulin-treated patient is in the held-out set (0 of 3), so performance for insulin users is untested.
    • The forecast is a single value exactly 2 h ahead, not a trajectory; the alert covers any reading in the next 2 h, so the two can differ.
    • No persona has eGFR below 60 (lowest 61.2 mL/min/1.73m²), so the simulator's eGFR <60 effects (slower insulin and sulfonylurea clearance, higher hypo propensity) are never exercised in this data.
    • No clinical validation. Research prototype, not a medical device; not for diagnosis or dosing decisions.

    Synthetic data only. Research prototype, not a medical device; not for diagnosis or dosing decisions.

    Uses only synthetic data, so no personal health data is processed (designed with DPDP Act 2023 principles in mind). Patient names are generated.

    Glucose bands follow ADA definitions: Level 1 hypoglycaemia <70 mg/dL, Level 2 <54 mg/dL, target range 70–180 mg/dL, marked hyperglycaemia >250 mg/dL.
